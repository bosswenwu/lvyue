# 履约云 · 采购合同履约管理

自建的采购合同履约跟踪系统。工作台、合同台账、预警中心、付款计划与现金流预测、按物料行的催货清单、附件归档、账号管理与操作留痕。

## 重要：必须用网址访问

浏览器在 `file://` 下会禁用数据库（IndexedDB）和加密接口（crypto.subtle），双击 HTML 打不开。三种正确的打开方式：

1. **本机试用** —— 双击 `启动.bat`，然后浏览器访问 http://localhost:8080
2. **上线（推荐）** —— 推到 GitHub 开 Pages，得到一个网址，手机电脑都能开
3. 放到公司任意 Web 服务器的目录下

## 一、先在本机跑起来

双击 `启动.bat` → 打开 http://localhost:8080

第一次进会让你建管理员账号，**密码由系统随机生成，只显示一次**，记下来。

此时数据存在这台电脑的浏览器里（本机模式），够你先把数据导进来验收。

## 二、把现有数据搬进来

1. 在旧系统点「导出 Excel」
2. Excel 打开 → 全选 `Ctrl+A` → 复制 `Ctrl+C`
3. 本系统「数据管理」→ 粘贴 → 「解析并预览」→ 「确认导入」

合同台账表和「报表中心 → 合同明细」的物料表都认，靠中文表头自动识别，按合同号合并。
表头里的「已到货金额 / 已开票金额 / 已支付金额」会作为**期初金额**记一条，之后的登记在此基础上累加。

支持的表头：合同号、订单编号、采购组织、项目、采购员、合同名称、供应商、合同总额、币别、签订日期、约定交期、承诺交期、装箱单日期、发货通知日期、要求到港日期、物流负责人、付款条件、交货地址、行号、物料编码、物料名称、规格型号、单位、订购数量、含税单价、价税合计、物料品牌、信息编码。

## 三、上线成网址（GitHub Pages）

```bash
git remote add origin https://github.com/你的账号/仓库名.git
git branch -M main
git push -u origin main
```

然后在 GitHub 仓库页：Settings → Pages → Source 选 `main` 分支 `/ (root)` → 保存。
一两分钟后得到网址：`https://你的账号.github.io/仓库名/`

> 仓库设为 Private 时 Pages 需要付费方案；用 Public 仓库也可以——**代码是公开的，但数据在 Supabase 里，靠账号密码保护，不会随代码泄露**。

## 四、开启多人共用（Supabase）

到这一步之前，每个人打开网址看到的是各自浏览器里的数据，互相不通。接上 Supabase 后就是同一份。

1. 去 https://supabase.com 注册，新建一个项目（免费额度足够，选新加坡节点最快）
2. 项目里 **SQL Editor** → 新建查询 → 把 `schema.sql` 全部内容粘贴 → Run（会弹出风险提示，属正常现象，选 **Run and enable RLS**）
3. **Authentication → Sign In / Providers → Email**，关掉 **Confirm email** 这个开关并保存。
   不关的话每建一个账号都会真的发确认邮件，对方得点邮件里的链接才能登录，免费额度发信也很有限，内部系统没必要留这道手续。
4. 到 **Project Settings → API Keys**，抄下两个值：
   - `Project URL`，形如 `https://xxxx.supabase.co`
   - **Publishable key**（新版叫法，等同于以前的 anon key，形如 `sb_publishable_...`）——**不要用 Secret key**，那个绝不能放进前端代码
5. 回到本系统「数据管理 → 接入云端」，填入这两个值，保存
6. 页面会重连到云端。此时**本机模式的数据不会自动搬过去**：先在本机模式「导出备份」，连云端后再导入 Excel 或还原备份

### 账号怎么发给同事

> **公开注册必须关掉。** 本仓库是公开的，代码里写着 Supabase 地址和 publishable key；而数据表的 RLS 是「任何登录用户可读写全部数据」。两者相加，只要 Supabase 的公开注册开着，**任何人都能自己注册一个账号，登进来看到全部合同、金额和供应商**。到 Authentication → Sign In / Providers → Email 把 **Allow new users to sign up** 关掉。
>
> 关掉之后，「用户管理 → 新建账号」这个按钮就用不了了（它走的正是公开注册接口）。给同事开号改到 **Authentication → Users → Add user**，勾上 **Auto Confirm User**，把邮箱和密码发给对方。新账号默认是「成员」，要升管理员在系统的「用户管理」页点「设为管理员」。

**云端模式下账号就是邮箱**，不再是随便起的用户名——这是 Supabase 账号系统的硬性要求。填一个真实存在的邮箱域名即可（如 `zhangsan@qq.com`、`@163.com`、`@gmail.com`），不需要对方真能收到信（第 3 步已经关掉确认邮件）。

「用户管理 → 新建账号」→ 填邮箱和姓名 → 系统生成 12 位随机密码（去掉了容易看错的 `0O1lI`）→ **只显示一次**，点「复制账号密码」发给对方。

忘记密码：目前本系统的「重置密码」按钮只对本机模式生效。云端模式下要去 Supabase 后台 **Authentication → Users** 找到对应账号手动重置，或者让对方用该邮箱走 Supabase 的找回密码流程（需要邮箱能收信）。

## 五、几个功能说明

**逾期怎么算** —— 取「承诺交期」，没有则回落「约定交期」，两者都没有会进「缺交期」预警。只要没全部到货且已过交期就算逾期，页面上会写明用的是哪个口径。

**付款计划怎么来** —— 按合同的「付款条件」文字自动拆节点：
- `预付30%，货到付60%，质保金10%` → 预付款（签订日到期）、到货款（交期到期）、质保金（交期+365 天）
- `月结30天` → 交期+30 天
- 认不出的文字 → 整单一个节点，可手工改

**现金流预测** —— 未来 12 周每周应付金额，第一根柱子含已逾期未付。没有付款节点的合同按合同待付余额和交期估算，所以建议先在「付款计划」页批量生成节点。

**催货清单** —— 按物料行算未到数量（订购 − 已到），可直接导出 CSV 发给供应商。前提是导入了物料明细并按行登记到货。

**附件** —— 单个文件上限 8MB。本机模式存浏览器，云端模式存 Supabase Storage。

## 六、登不上去怎么办

登录页现在会把失败的**真实原因**写出来，先照着报错看，不要一上来就怀疑密码：

| 报错里出现 | 实际原因 | 怎么修 |
|---|---|---|
| 账号或密码不对 | 真的是密码错了 | 云端模式账号必须是完整邮箱。忘了密码到 Supabase 后台 **Authentication → Users** 重置 |
| 云端密钥（API key）被拒绝 | 浏览器里存的是旧密钥 | Supabase 后台 **Project Settings → API Keys** 抄最新的 Publishable key，回「数据管理 → 接入云端」重填 |
| 连不上云端服务器 / 服务器返回 5xx | 项目被暂停或断网 | Supabase 免费项目长时间没人访问会自动暂停，到后台点 **Restore** |
| 登录太频繁，被限流 | 连点太多次 | 等一两分钟 |
| 账号密码是对的……随后读取数据时出错 | 认证过了，是表或 RLS 的问题 | 在 SQL Editor 里把 `schema.sql` 和 `schema_v2_roles.sql` 跑一遍 |

> **为什么会「用得好好的突然登不上」**：以前程序会把代码里的默认云端配置抄一份存进浏览器，之后就一直用那份旧的。所以 Supabase 那边一换密钥（比如从旧 anon key 换成 `sb_publishable_...`），老浏览器还拿着作废的旧密钥去登，必然被拒——而换台新设备打开却是好的。现在只有在「接入云端」里手工填过的地址才会被记住，默认配置每次都以代码里的为准，这个坑不会再出现。升级后所有人需要重新登录一次。

> **免费项目会自动暂停**：Supabase 免费版连续 7 天没有任何 API 请求就会把项目停机，届时所有人都登不上，浏览器上表现为连接被直接关闭（`ERR_CONNECTION_CLOSED`）。到 Supabase 后台点 **Restore** 即可恢复，数据不会丢。仓库里的 `.github/workflows/keep-supabase-awake.yml` 每两天自动请求一次云端来避免这件事；真要保证不停机得升付费版。

## 七、备份

本机模式的数据只在这台电脑的浏览器里，**清浏览器数据或换电脑就没了**。请定期在「数据管理 → 导出备份」存成 JSON 文件。

云端模式也一样要自己备份：**Supabase 免费版不做自动备份**（控制台首页 Last backup 显示 No backups），付费版才有每日备份。所以云端模式下同样请定期「导出备份」。
